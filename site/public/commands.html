04/Commands

Command reference

Claude Code invokes each command as /flow-…, Codex as $flow-…. A checkout loaded with --plugin-dir namespaces them as /devflow:flow-….

core

/flow-new

Codex: $flow-new · source

Initialize a Flow project (greenfield or existing repo) — creates .planning/ with requirements, roadmap, and state. Use when starting Flow work in a repo that has no .planning/ directory. Supports --provider native|claude|codex and --tier full|lite.

/flow-migrate

Codex: $flow-migrate · source

Explicit-only: the host will not let the model start it. A person types it.

Convert a GSD (open-gsd/gsd-core) project's .planning/ to DevFlow format - history and context preserved, originals archived. Use once per GSD project, instead of /flow-new. Supports --provider native|claude|codex.

/flow-plan

Codex: $flow-plan · source

Plan one roadmap phase - discuss decisions, optional research, write plans, check them. Args - phase number, plus optional --auto (no questions), --gaps (replan from verification gaps), --research, --panel (parallel scope/feasibility/coherence review of the plans), --review (publish the plan graph as a review page). Use before executing a phase. Supports --provider native|claude|codex.

/flow-execute

Codex: $flow-execute · source

Execute all plans of a phase in dependency waves via parallel executor subagents, then verify. Args - phase number, optional --auto (skip confirmations). Use after /flow-plan. Supports --provider native|claude|codex.

/flow-verify

Codex: $flow-verify · source

Re-verify an executed phase against its must_haves and walk the user through batched human checks. Args - phase number. Use standalone after changes, or when /flow-execute ended with human checks pending. Supports --provider native|claude|codex.

auto

/flow-next

Codex: $flow-next · source

Advance the project exactly one step (plan, execute, replan gaps, or harden) and stop with a FLOW status line. The driver for autonomous operation via /goal or /loop. Use to make progress without deciding what comes next.

ad-hoc

/flow-quick

Codex: $flow-quick · source

Do a small ad-hoc task with Flow guarantees (atomic commits, deviation rules, logged) without phase ceremony. Args - task description. Use for fixes and small features outside the roadmap. Supports --provider native|claude|codex.

/flow-debug

Codex: $flow-debug · source

Systematic debugging with persistent hypothesis state that survives sessions. Args - symptom description, --incident <pasted alert, ServiceMonitor output, or App Insights/incident link>, or no args to resume the newest open debug file. Use when cause is unknown. Supports --provider native|claude|codex.

/flow-oracle

Codex: $flow-oracle · source

Ask an external frontier model for a second opinion via a curated context bundle. Args - question, plus optional --panel (multi-model cross-check), --followup NNN, or no args to resume the newest open consult. Use when stuck or before a high-stakes decision. Supports --provider native|claude|codex.

/flow-status

Codex: $flow-status · source

Show where the project is and what to run next; --all boards every DevFlow project on the machine, --pause records a clean stopping point, --reset-run re-arms the autonomous loop rails. Use at session start, when lost, when tracking parallel work, or before stepping away.

/flow-audit

Codex: $flow-audit · source

Read-only cross-artifact consistency check across REQUIREMENTS, ROADMAP, plans, SUMMARYs, VERIFICATION and STATE - coverage both directions, drift, unmeasurable criteria, open clarifications, principle conflicts. Use before executing a phase, before /flow-harden, or when the planning docs feel out of sync. --export assembles an agent-activity evidence pack (who had access, what changed, who approved) for a vendor or compliance review. --docs checks README/docs claims (paths, scripts, package scripts, make targets, env names) against the tree - use before a docs-only PR. --drift checks what the plan, STATE, decisions and CLAUDE.md say against the code and git history - use when a cold session is about to trust the docs.

/flow-todo

Codex: $flow-todo · source

Capture an idea or task for later without derailing current work; no args lists open items. Args - the idea text, or --incident <pasted alert, ServiceMonitor output, or App Insights/incident link>.

/flow-undo

Codex: $flow-undo · source

Explicit-only: the host will not let the model start it. A person types it.

Undo unpublished commits on the current feature branch - preview what would be removed, ask the human, then apply only on explicit confirmation, keeping a backup ref. Args - the commit to return to (SHA or rev). Explicit-only; never touches published work, a merge, or the base branch.

/flow-second-opinion

Codex: $flow-second-opinion · source

Explicit-only: the host will not let the model start it. A person types it.

Read-only second-opinion review of one pull request by Grok Build and Codex CLI (trial through 2026-10-30) - scope-guarded to allowlisted non-fork, non-InformativeResearch repos, throwaway checkout, each tool in its read-only sandbox, local report plus a trial-log row; posts ONE combined PR comment only with --post. Args - PR URL, optional --tools codex,grok, --post. Explicit-only.

parallel

/flow-workstream

Codex: $flow-workstream · source

Explicit-only: the host will not let the model start it. A person types it.

Manage parallel workstreams as git worktrees - new, list, drop. Args - new <slug> [--phase N], list, drop <slug>. Use to run more than one phase or feature at once without two agents fighting over one checkout.

policy

/flow-test-policy

Codex: $flow-test-policy · source

Agent test-layer policy for DevFlow product work. Prefer integration/behavior as the feedback driver; thin units for pure logic/regression pins only; forbid coverage theater and classic unit-TDD as default. Use when planning, executing, verifying, or reviewing tests. Supports --provider native|claude|codex.

memory

/flow-map

Codex: $flow-map · source

Build or refresh codebase memory (MAP.md), distill docs (--docs path), or consolidate learnings (--refresh). Use on existing codebases before planning, or when the map is stale. Supports --provider native|claude|codex.

design

/flow-design

Codex: $flow-design · source

Link a Claude Design (claude.ai/design) design-system project to this repo and pull it locally as hard UI constraints; --refresh re-pulls. Use up front on projects with a UI, or when the design system changed. Supports --provider native|claude|codex.

guardrails

/flow-hooks

Codex: $flow-hooks · source

Explicit-only: the host will not let the model start it. A person types it.

Scaffold deterministic PreToolUse hooks (base-branch guard, protected-paths guard, secret-scan guard, dependency guard, destructive-git guard) into .claude/settings.json, hardening five of DevFlow's instruction-only hard rules so they hold even if an agent ignores them. Args - optional --only base,secret,paths,deps,destructive to install a subset; default installs all five. No .planning/ required.

integrate

/flow-pr

Codex: $flow-pr · source

Push the current feature branch to origin and open a pull request against upstream (or the base branch) from verified work. Use when a phase or body of work is ready to integrate. Args - optional --adversarial (review through the peer provider, then adjudicate findings into a durable ledger). Supports --provider native|claude|codex.

/flow-ci

Codex: $flow-ci · source

Drive an open pull request to green - watch checks, fix failures, triage and answer bot review comments, resolve threads. Args - optional PR number, --auto. Use after /flow-pr, or any time a PR is red or has unread review comments.

triage

/flow-triage

Codex: $flow-triage · source

Pre-screen open, externally-authored pull requests against ARCHITECTURE.md/REQUIREMENTS.md/conventions.md and produce a merge-readiness summary — flags only the promising ones for human review. Args - optional PR number(s) to screen specific PRs, --all (include every open PR and every verdict tier, not just flagged ones), --export (persist the report under .planning/triage/). Supports --provider native|claude|codex. Prototype: drafts responses, never posts, closes, or merges anything.

deploy

/flow-harden

Codex: $flow-harden · source

Production-hardening pass - audit the codebase against the Aspire production checklist, fix findings via a hardening plan. Use after all roadmap phases are verified, before /flow-uat. Supports --provider native|claude|codex.

/telemetry-readiness

Codex: $telemetry-readiness · source

Check that every deployed service in an Aspire/ACA project emits traces, metrics and logs to a workspace-based Application Insights, and that the Azure sinks exist and are wired to it. Read-only — reports, never fixes. Use at scaffold (advisory), when a service is added, before a PR, and before and after a deploy. Works in DevFlow, GSD and plain repos. Args - --scope code|platform|all, --env <name>, --services <list>.

/flow-uat

Codex: $flow-uat · source

Deploy to the UAT environment on Azure (provisioning on first deploy) and generate the human acceptance test plan whose sign-off gates production. Use after /flow-harden.

/flow-release

Codex: $flow-release · source

Explicit-only: the host will not let the model start it. A person types it.

Deploy to production on Azure, gated on UAT sign-off matching the current commit. Use after /flow-uat sign-off.

deploy (opt-in)

/flow-prod-readiness

Codex: $flow-prod-readiness · source

Explicit-only: the host will not let the model start it. A person types it.

Read-only production-readiness review of one deployed app's platform posture - edge geo-filter, WAF with OWASP rules plus a false-positive check, identity on every request, private database, secrets out of code, audit logging, tested restore, minimum capacity and graceful shutdown, monitoring others can read. Each item gets pass, gap or unknown and an owner. Run once per app before go-live and again after a major infrastructure change; never per PR. Explicit-only. Args - --app <name>, --url <base url>, --env <name>, --out <path>.

/flow-security-audit

Codex: $flow-security-audit · source

Explicit-only: the host will not let the model start it. A person types it.

Optional pre-production security audit gate (Cloudflare harness patterns). Opt-in only — not part of default /flow-* runs. Use when explicitly asked to security-audit / pen-test / full vuln review before UAT/prod. Modes: guidance (default for questions) vs full audit (explicit). Supports --provider native|claude|codex.
