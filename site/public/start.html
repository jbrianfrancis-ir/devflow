00/Install

Install DevFlow

DevFlow is a plugin. Add its marketplace, install it, and check it with one command in an empty directory.

AWhat you need

A host
Claude Code; a local Codex client: the CLI, the app or the IDE extension; or GitHub Copilot CLI or VS Code agent mode. Codex cloud and the Copilot cloud agent on github.com are not supported.
git
Every project is a git repository. DevFlow works on a flow/<slug> branch and never commits to main.
Python 3
DevFlow's helper scripts (plan lint, worktree landing, the cross-provider bridge) are standard-library Python, run as python3.
gh
The GitHub CLI, authenticated, for /flow-pr and /flow-ci. Planning and executing work without it.
Azure and azd
Only for projects that deploy, at /flow-uat and /flow-release. A library, CLI or docs repo sets deploy.tool to null and never needs them.

BClaude Code

Run these inside Claude Code:

/plugin marketplace add jbrianfrancis-ir/devflow
/plugin install devflow@devflow

Commands are /flow-new, /flow-plan and so on. A project that DevFlow initializes also records the plugin in its .claude/settings.json, so a fresh Claude session in that repo installs it on its own.

CCodex CLI, app or IDE

codex plugin marketplace add jbrianfrancis-ir/devflow
codex plugin add devflow@devflow

Start a new Codex thread after installing. Codex invokes the same skills with a $ prefix: $flow-new, $flow-plan, $flow-execute. Codex installs at user scope, and a project skill never edits your Codex configuration.

DGitHub Copilot CLI or VS Code

Run these in a shell. In a Copilot CLI session, /skills list then shows the flow-* skills:

copilot plugin marketplace add jbrianfrancis-ir/devflow
copilot plugin install devflow@devflow

In VS Code agent mode (agent plugins are in preview), set chat.plugins.enabled to true, add the marketplace jbrianfrancis-ir/devflow and install DevFlow. A plugin the CLI installed also appears in VS Code. The Copilot cloud agent on github.com is not supported. Steps are in docs/getting-started-copilot.md.

ECheck the install

In an empty git repository, ask for status. With no .planning/ directory there is nothing to report, so it names the next step and stops at a gate, because /flow-new needs your answers.

This run loaded DevFlow from a checkout for one session, which is why the command reads /devflow:flow-status. An installed plugin answers to /flow-status.

FRun a checkout for one session

For trying a branch or contributing. This changes no installed plugin and no marketplace. From a scratch directory:

claude --plugin-dir <path-to-checkout>/plugins/devflow

Skills are then namespaced by the plugin name, so type /devflow:flow-status. Headless works too:

claude --plugin-dir <path-to-checkout>/plugins/devflow -p "/devflow:flow-status" --effort low

No session-only load path has been checked for Codex, so none is listed. Details are in docs/installation.md.
