05/Feedback

Report what broke, or what got in the way

Feedback goes through GitHub Issues on the DevFlow repository. There is no forum or chat channel, and GitHub Discussions is not turned on for this repository.

AWhere

  • Report a bug

    A command, skill or agent did the wrong thing. The form asks for the command, what happened, what you expected, repro steps, your .planning/ state and your environment.

  • Suggest a change

    Friction, a missing step, a gate in the wrong place. The form asks which skill, agent, reference or template should change, and whether it adds to what each command loads.

  • Read open issues

    Search first. If someone already reported it, add your case to theirs.

BWhat makes a report useful

The FLOW line
The last line the command printed, for example FLOW: BLOCKED | … | next: …. It names the state and the step DevFlow thought came next.
STATE.md Position
The ## Position block of .planning/STATE.md, and the frontmatter of any SUMMARY or VERIFICATION file involved.
Versions
The DevFlow version (in the plugin's plugin.json), your host and its version, and the model.
The command
Exactly what you typed, flags included, and whether it ran under /goal, /loop or by hand.

Issues are public. Leave out secrets, tokens, connection strings, customer data and private repository content. Paste the shape of a value, never the value.

CChanging DevFlow yourself

Pull requests are welcome. DevFlow's own rules apply to it: work on a branch, keep the size budget, and include the host smoke receipt from the pull request template when you touch plugins/devflow/. The one-session load on the install page is how you test a checkout.
