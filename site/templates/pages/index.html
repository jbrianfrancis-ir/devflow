Plugin for Claude Code and Codex/MIT/open source

A development process for coding agents, from first requirements through release, and back when production breaks.

DevFlow is token-efficient spec-driven development for Claude Code and Codex. It writes your requirements, roadmap and state to .planning/, runs each plan in a fresh-context subagent, and has an independent verifier check the result against commands it actually ran. When the evidence isn't there, the verifier says so instead of guessing.

01The loop

Each phase of your roadmap goes through the same steps. You can type each one, or let /flow-next pick the next step and run it. It stops at every human gate either way.

  1. /flow-new

    Asks one bounded round of questions, or works from your description, then writes requirements, a phased roadmap, architecture constraints and state on a new flow/<slug> branch.

  2. /flow-plan N

    Settles the phase's open decisions, writes executable plans, and has a plan-checker reject any plan an executor could not run without guessing.

  3. /flow-execute N

    Runs the plans in dependency waves, one fresh-context executor per plan with an atomic commit per task, then a separate verifier checks the phase goal.

  4. /flow-status

    Reads .planning/ and prints where you are and the exact next command. Run it whenever you come back.

  5. /flow-pr

    Human gateScans for secrets, reviews the outgoing diff through independent lenses, pushes the branch and opens the pull request. Typing /flow-pr yourself is the approval. Under /goal or /loop it stops and asks first. Merging is always yours.

02What a session leaves behind

Chat history is not where DevFlow keeps anything. A cold session reads .planning/STATE.md first and knows the phase, what is in flight and the next command.

Each file on the right exists in the scratch project from the first-workflow run.

STATE.md
Position, open gate, loop counters, next command. Size-capped and rewritten in place.
REQUIREMENTS.md
REQ-NN requirements, measurable SC-NN success criteria, assumptions, and inline [NEEDS CLARIFICATION] markers.
ROADMAP.md
Phases, each with a one-line goal and the requirement IDs it owns.
ARCHITECTURE.md
Your stack at major versions, forbidden items and principles. Agents treat it as law.
phases/NN-*/
Plans, per-plan SUMMARYs, and the verifier's VERIFICATION.md.
DECISIONS.md
Append-only record of every human gate: what was asked, what was answered, by whom, at which SHA.

03What it will not do on its own

These hold under /goal and /loop too. The full gate list is in autonomy.md.

Commit to main
Work lands on a flow/<slug> branch and integrates by pull request.
Open or merge a PR
Opening a pull request upstream and merging one are human gates.
Certify a guess
A truth the requirements never settled goes to you as a human check, not a pass.
Ship a secret
A fail-closed secret scan guards every commit and push. A hit stops the run and the value is never echoed.
Add a dependency
A new package, or a major-version change, waits for your approval and is logged.
