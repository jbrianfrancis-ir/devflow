<task type="auto">
  <name>Task 1: Build the fixture harness</name>
  <files>tests/test_check_links.py</files>
  <action>
`unittest`, stdlib only. Load the hyphenated script with
`importlib.util.spec_from_file_location("check_links", <repo>/scripts/check-links.py")`, exactly as
`tests/test_flow_agent.py` does — hyphens are not valid module names. Resolve the repo root from
`__file__`, never a hardcoded absolute path.

Build fixture repos under `tempfile.mkdtemp()` with `addCleanup(shutil.rmtree, ...)`; never mutate the
repo's own tracked files. A fixture writes a few `.md` files plus the targets they reference, then calls
01-01's pinned seam — `check(root)` with `root` set to the fixture directory, returning the failure list.
Assertions read that list; no test shells out to the CLI or points the checker at this repo.

`check(root)` enumerates via `git -C <root> ls-files '*.md'`, so each fixture must be a real git repo:
`git init` the temp directory and `git add -A` after writing the files. Run git with an env that does not
inherit the developer's global config (`GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_SYSTEM=/dev/null`), so
the fixture behaves identically on CI. No commit is needed — `git ls-files` reads the index.

Land one case with this harness: a **clean fixture whose references all resolve returns an empty failure
list**. This is the anti-tautology anchor — without it, a checker that always failed would pass every test
in Task 2.
  </action>
  <verify>`python3 -m unittest tests.test_check_links -v` reports OK; `git status --porcelain -- scripts tests docs plugins README.md` is empty afterwards.</verify>
  <done>Harness builds and tears down temp fixtures, loads the hyphenated script, and the clean-fixture case passes.</done>
</task>

  <name>Task 2: Cover every reference kind, the scope boundary, and each skip rule</name>
  <files>tests/test_check_links.py</files>
  <action>
Add, on the Task 1 harness:
- One failing case per reference kind: `[text](missing.md)`; `[text](#no-such-heading)` against a file with
  known headings; a backticked `some/missing.py`; a backticked `{devflow_root}/references/missing.md`.
  Each asserts the returned failure names the offending file, its line number, and the target.
- Anchor positive: `[text](#a-real-heading)` against a matching heading passes, exercising the slugger in
  both directions.
- Scope (REQ-09d): a broken backticked reference under `plugins/devflow/templates/` and one under
  `.planning/` in the fixture each leave the returned failure list empty.
- Skip rules (REQ-09e), one assertion per rule so a future over-tightening names which rule it broke: a
  backticked command line containing a space (R1), a `*`-glob token (R2), an `NN-slug` placeholder path
  (R3), and a `.planning/`-rooted token (R4) each produce no failure.
- R5 needs **two** assertions, because R5 is per-base and a skip-only case would pass under the wrong
  (root-only) reading too. In one fixture: (a) a file in a subdirectory writes a backticked token whose
  first segment is *not* a top-level entry of the fixture root but *is* a top-level entry of that file's own
  directory — e.g. `sub/a.md` writing `` `helpers/missing.py` `` with `sub/helpers/` present (git tracks no
  empty directory, so write a real `sub/helpers/present.py` and `git add -A` it) and `sub/helpers/missing.py`
  absent. That token must be **checked**, and the returned failure must name
  `sub/a.md`, its line, and the target. (b) The same file writes `` `codebase/MAP.md` ``, whose first
  segment is a top-level entry of no base of that token, and it produces no failure. Assertion (a) is what
  distinguishes the correct rule from the root-only one; do not drop it for a skip-only case.
Name each test for the rule or requirement it pins, not `test_1`.
  </action>

  <done>All four kinds, the anchor positive, both scope exclusions, and all five skip rules are covered by individually named passing tests — R5 by two, its skip case and its checked-against-another-base case.</done>
