<task type="auto">
  <name>Task 1: Write scripts/check-links.py</name>
  <files>scripts/check-links.py</files>
  <action>
Stdlib only (`re`, `os`, `sys`, `subprocess` for git). No network, no pip.

Module contract — 01-02's tests import this file and drive it against temp-directory fixtures, so pin
exactly this shape:
- `def check(root)` — enumerates the markdown under `root` (not the current working directory) and
  returns the list of failures, each carrying file, line, target, and reason. It prints nothing.
- `def main(argv=None)` — resolves the repo root, calls `check(root)`, prints the report, returns the
  exit code.
- The only top-level execution is `if __name__ == "__main__": sys.exit(main())`. Importing the module
  must run no check and read no file, so a fixture test can load it without touching this repo.

Scope (REQ-09d): `check(root)` enumerates `git -C <root> ls-files '*.md'` minus
`plugins/devflow/templates/**` and `.planning/**` — 50 files today at the repo root. Every path it
resolves is relative to `root`, so the `{devflow_root}` rewrite and the "repo root" resolution root below
both mean `root`, never a captured absolute path.

Kinds:
- REQ-09a `[text](target)` — strip `<>` and any title suffix; skip `http://`, `https://`, `mailto:`. Bare
  `#frag` checks the current file's headings; `path#frag` checks path then that file's headings. Slug =
  lowercase, drop all but word chars/space/hyphen, spaces→hyphens. Harvest ATX (`#`..`######`) at minimum.
- REQ-09b backticked tokens containing `/` and ending `.md`/`.py`/`.json`/`.yml`.
- REQ-09c a `{devflow_root}/` prefix rewrites to `plugins/devflow/` before resolution.

Skips — rules only, never an allowlist file (REQ-09e):
R1 token contains whitespace (a command, e.g. `python3 scripts/validate-plugin.py`);
R2 token contains `* < > { } , |` after the rewrite (a family, not a file);
R3 a segment is or begins with placeholder `NN`/`NNN`/`MM`/`YYYY` (`NN-slug`, `NN-MM-PLAN.md`);
R4 token starts `.planning/` or `~/`;
R5 the token's first segment is neither `.`/`..` nor a top-level entry of **any of the token's resolution
bases** — the same bases resolution uses below: `root`, the referring file's own directory, and
`<root>/plugins/devflow/` when the file lives under it. Entries come from `git -C <root> ls-files`, never a
literal list. Apply R5 per base, not against `root` alone: `templates/journal.md` written by a file under
`plugins/devflow/` survives, because `templates` is a top-level entry of that base even though it is not one
of `root`; `codebase/MAP.md` and `deploy/PIPELINE.md` are skipped, because no base of theirs has such an
entry — they name paths inside a *consuming* project. R5's known cost, narrowly: a first-segment typo goes
unseen only when the mistyped segment matches no top-level entry of any of that token's bases (`docz/x.md`).
A typo in any later segment is still reported, as is a first segment that names a real directory but a
missing file under it — including a broken `templates/nope.md` written from inside `plugins/devflow/`.

Resolution: a surviving token must exist under at least one base — `root`, the referring file's own
directory, and `<root>/plugins/devflow/` when the file lives under it (`conventions.md` correctly writes both
`docs/blitzos.md` and `templates/journal.md`).

Reporting: collect all failures; print one `path:line: <target> — <reason>` each plus a count; exit 1 if
any. Failure to enumerate files exits non-zero as "could not check", never silently clean.
  </action>
  <verify>`python3 scripts/check-links.py; echo $?` runs and reports. `python3 -S -E scripts/check-links.py` runs. Loading it as a module runs nothing and exposes the seam: `python3 -c "import importlib.util,sys; s=importlib.util.spec_from_file_location('check_links','scripts/check-links.py'); m=importlib.util.module_from_spec(s); s.loader.exec_module(m); print(callable(m.check))"` prints `True` and no failure lines.</verify>
  <done>Script prints file, line, target, and reason per failure; exit 1 on any, 0 on none; `check(root)` is importable and side-effect free.</done>
</task>
