<task type="auto">
  <name>Task 1: Write scripts/check-fenced-paths.py</name>
  <files>scripts/check-fenced-paths.py</files>
  <action>
Stdlib only (ARCHITECTURE → Forbidden: no third-party package, ever). The guard answers one question:
**does a repo path that exists sit inside a fenced code block on a page this project writes** — because
`check-links.py` masks fences, so such a path is a reference CI silently stopped covering (D-15).

Structure, mirroring `check-links.py`'s own seam split (`LEARNINGS.md`: `main()` resolving the root from
the cwd is the unsafe part; the explicit-root function is the safe seam):

- `_load_checker(root)` — `importlib.util.spec_from_file_location("check_links", root / "scripts/check-links.py")`,
  exec the module, return it. Any failure (missing file, `OSError`, `SyntaxError`) raises a
  `GuardUnavailable` the caller turns into a non-zero **could not check** exit — never a clean one.
- `SCOPE`: `README.md` plus `sorted(glob("docs/*.md"))`, minus `FROZEN = ("docs/blitzos.md",
  "docs/status-contract.md")`. Keep `FROZEN` a named constant with a one-line comment saying why:
  both are out of scope for this project and `status-contract.md` already carries
  `{devflow_root}/scripts/flow-fleet.py` inside a fence. README.md is in scope because this phase adds
  fenced blocks to it too.
- `scan(root)` → `(violations, files_scanned, fenced_lines)`. Per file: `lines = text.splitlines()`,
  `front = mod._frontmatter_mask(lines)`, `mask, unterminated = mod._code_fence_mask(lines, front)`.
  `unterminated is not None` → a violation naming that line. For each line where `mask[i]` and not
  `front[i]`, find tokens matching `[A-Za-z0-9_.{}-]+(?:/[A-Za-z0-9_.{}-]+)+\.(?:md|py|json|yml)`
  (the phase-02 token shape, which is `check-links.py`'s backticked-path shape); skip tokens starting
  `.planning/` or `~/` (checker rule R4); rewrite a leading `{devflow_root}` to `plugins/devflow`;
  report the token when the resolved path exists under `root`. A path that does not exist was never
  checkable prose anyway — the guard is about coverage this phase would remove, not about typos.
- `main()` — root from `git rev-parse --show-toplevel` (cwd-relative, like the checker's `main()`),
  print one `<file>:<line>: <token>` line per violation, then the summary
  `N violations, F files scanned, L fenced lines`; exit 1 on violations, 2 on could-not-check, 0 otherwise.

Do **not** reimplement the fence rules. Every judgment about what is fenced comes from the imported
functions; that is what makes this parity rather than a second guess at the same rule.
  </action>
  <verify>
`python3 scripts/check-fenced-paths.py` → exit 0, summary `0 violations, 10 files scanned, 12 fenced lines`
(probed at phase start; F/L may differ only if a page changed).
Two distinct cwd cases, two commands — the root comes from `git rev-parse --show-toplevel`, not from the cwd:
- **From a subdirectory of the repo:** `cd docs && python3 ../scripts/check-fenced-paths.py` → exit 0 and the
  *identical* summary line (same F, same L), because the root resolved to the repo, not to `docs/`.
- **From outside any repo:** `d=$(mktemp -d) && cd "$d" && python3 <abs-repo>/scripts/check-fenced-paths.py`
  → exit non-zero with a could-not-check message and no `0 violations` line. (`mktemp -d` is under `/tmp`,
  where `git rev-parse --show-toplevel` fails — confirmed; do not substitute a path that might sit in a repo.)
Fail-closed, and it must be the *loader* failing, not the root resolution — so the fixture is a real repo
with no checker in it: `d=$(mktemp -d) && cd "$d" && git init -q . && mkdir scripts && cp <abs-repo>/scripts/check-fenced-paths.py scripts/ && python3 scripts/check-fenced-paths.py`
→ exit 2, message naming the missing `scripts/check-links.py`, no `0 violations` line. An empty dir alone
would red for the wrong reason (no repo) and leave `GuardUnavailable` untested from the CLI.
  </verify>
  <done>The script exists, runs clean on this repo with non-zero scanned counts, and cannot report success it did not establish.</done>

<task type="auto">
  <name>Task 2: Write tests/test_check_fenced_paths.py — the parity proof</name>
  <files>tests/test_check_fenced_paths.py</files>
  <action>
`unittest`, stdlib only, same tempdir-fixture style as `tests/test_check_links.py` (build a tree, drive
`scan(root)`, tear down; `GIT_CONFIG_GLOBAL=/dev/null` if you shell out to git — this guard does not need
a git tree, so prefer not to). Each fixture writes `scripts/check-links.py` (copy the real one),
`plugins/devflow/references/conventions.md` (so the referenced path genuinely exists), and the pages
under test.

Cases, one test each:
1. **``` fence** — `docs/a.md` with `plugins/devflow/references/conventions.md` inside a ``` block → one violation on that line.
2. **`~~~` fence** — same content in a `~~~` block → one violation.
3. **Tab-indented fence** — opener and closer indented with a literal tab (`_code_fence_mask` matches the
   *stripped* line, so the checker masks it) → one violation.
4. **Toggle inversion, assertion pair** — `docs/d.md`:
   ```` ``` ```` / `~~~` / `<path>` / ```` ``` ```` / blank / `<path> prose`.
   Assert **both**: the path on the line after the `~~~` is reported (it is still inside the ``` block),
   and the prose path after the closing ``` is **not**. Add a comment recording why both halves are
   asserted: the phase-02 awk toggled on any fence-shaped line, so it reported the prose path and missed
   the fenced one — an inverted guard that is fail-open where it matters and noisy where it does not, and
   a one-sided test would have passed on it.
5. **Unterminated fence** — a page opening ``` with no closer → violation naming the opener line.
6. **Non-existent path inside a fence** — `docs/nope.md` with `docs/not-a-real-file.md` fenced → no
   violation (nothing lost coverage).
7. **Frozen pages excluded** — a fixture `docs/status-contract.md` with a fenced real path → no violation.
8. **This repo is clean** — `scan(REPO_ROOT)` returns no violations and a non-zero file count, so the
   suite fails the day someone fences a real path into README or a `docs/` page. This is the case that
   makes G3 a standing gate rather than a one-off command.
9. **Could-not-check is not clean** — point the loader at a tree with no `scripts/check-links.py` and
   assert the guard raises / exits non-zero rather than returning an empty violation list.
  </action>
  <verify>
`python3 -m unittest tests.test_check_fenced_paths -v` → OK, 9 tests.
Mutation check, run and then revert: delete the `~~~` alternative from the guard's fence handling by
pointing case 2 at a hand-rolled toggle (or temporarily stub `_code_fence_mask` with the phase-02
toggle-on-any-fence behaviour) and confirm cases 2 and 4 fail — a parity test that passes against the
old broken rule proves nothing. Record in the SUMMARY that the mutation was run and reverted.
Then the full smoke: `python3 scripts/validate-plugin.py && python3 -m unittest discover -s tests -v && python3 scripts/check-links.py` → exit 0, `0 failures, 179 references checked`.
  </verify>
  <done>Nine tests pass, the four fence forms and the inversion pair are asserted from both sides, the suite is picked up by `unittest discover`, and the smoke is green with the reference count unmoved at 179.</done>
