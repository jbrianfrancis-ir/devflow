  <files>docs/README.md</files>
  <action>
Create `docs/README.md`: one `# ` heading, an opening line of at most two sentences saying what this
directory is and pointing back to the repo README as a markdown link whose target is `../README.md`
(the house rule below forbids a bare backticked path, so the back-pointer *is* a link — which is why the
arithmetic truth counts sibling targets only and this one sits outside the eleven), then an entry for **every**
`docs/*.md` except itself — the eleven named in `OPENING-MAP.md` §7.

Entry form, one line each: `- [providers.md](providers.md) — which provider runs a role, and which
model tier it gets.` Sibling target (never `docs/providers.md`), clickable markdown link (never a bare
backticked path), and a *what it answers* clause — what question sends a reader to that page, not a
restatement of its title. Read each page before writing its line; a wrong one-liner is worse than none
because it routes readers away from the answer.

Ordering and grouping are yours (CONTEXT.md → Discretion). A reader arriving from README's
`## Documentation` should see the getting-started pages before the contracts; `blitzos.md` and
`status-contract.md` are integration contracts, not tutorials, and read best grouped as such — but do
not retitle or edit either page: both are out of scope (PROJECT.md → Out of scope).

REQ-12 does not fire here — an index of this repo's own pages has no `references/*.md` counterpart, so
it owns its content outright. Keep the register: dense, terse, load-bearing, no filler.

Nothing path-shaped goes inside a fenced block (D-15); the simplest way to honour that is to use no
fence at all on this page. `git add docs/README.md` before running the gates — the checker only sees
tracked files, and an untracked page reports a misleadingly green smoke.
  </action>
