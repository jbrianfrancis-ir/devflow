bump: minor
Releases on merge, no more version conflicts: a PR that changes `plugins/devflow/**` adds one `changes/<slug>.md` fragment (first line `bump: major|minor|patch`, then this bullet) and edits no version or CHANGELOG entry. On push to main, `release.yml` runs new `scripts/next-release.py`: the latest `vX.Y.Z` tag, bumped by the highest `bump:` among fragments added since it, becomes a new tag and GitHub Release whose notes are those bullets. Nothing is committed back, and fragments stay as history. The plugin manifests drop `version`, because a committed version holds Claude Code installs on the cached copy until it changes, so installs now follow `main` commits; `validate-plugin.py` rejects a `version`. `flow-copilot.py` labels a pack `unversioned` when the manifest has none, and `/flow-status --all` counts a 12-hex commit-SHA install as a known build, not `VER-UNKNOWN`. New `scripts/check-change-fragment.py` (replaces `check-version-bump.py`) fails a shipped change with no fragment, a malformed fragment, an added manifest `version` line, or an edit to a released CHANGELOG entry. `/flow-pr` step 2c writes a fragment in any repo with a `changes/` directory.
