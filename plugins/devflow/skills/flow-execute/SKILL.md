---
name: flow-execute
description: Execute all plans of a phase in dependency waves via parallel executor subagents, then verify. Args - phase number, optional --auto (skip confirmations). Use after /flow-plan. Supports --provider native|claude|codex.
---

# flow-execute

**Host setup**: resolve `devflow_root` and follow `{devflow_root}/references/hosts.md` before doing anything else.

**Agent provider**: accept `--provider native|claude|codex`. Resolve and dispatch every role in this run exactly as `{devflow_root}/references/hosts.md` specifies. The selected provider applies to all delegated roles unless this skill explicitly calls an external consultation engine. A missing or failed peer is fail-closed; report `FLOW: BLOCKED` with remediation and never fall back silently.

Context rules: read `.planning/STATE.md` first; pass subagents paths, never contents; read plan/SUMMARY **frontmatter only** in this session; keep output terse — the executors do the work.

Test layer: executors follow `{devflow_root}/references/test-policy.md` — integration/behavior first; thin units only for pure logic or regression pins; no post-hoc coverage suites.

**Pre-flight**: phase dir has `NN-MM-PLAN.md` files; working tree clean (`git status --short` — otherwise ask to commit/stash, or proceed on explicit confirmation). On the feature branch (`git.branch` from config), never the base branch — switch to/create it off `git.base` if needed (per `{devflow_root}/references/conventions.md`). Surface any `user_setup` items from plan frontmatter and confirm they're done before starting. **Plan lint**: from the repo root run `python3 {devflow_root}/scripts/flow-plan-lint.py .planning/phases/NN-slug` — deterministic, so run it yourself (rules in plan-format.md; it skips plans whose SUMMARY exists). Any finding, `R0 could-not-check` included, stops the run before any executor is spawned: print the findings and end with `FLOW: BLOCKED | plan lint: <n> findings | next: fix the plans (or /flow-plan N --gaps), then /flow-execute N`. An R6 on a plan written before `files_new` existed names a file the plan creates but never declared — the fix is adding it to that plan's `files_new`. **Worktree pre-flight**: every plan file is committed (`git ls-files --error-unmatch <plan>`) — a task worktree sees only committed files. When executors run as native Claude agents, the host nests their worktrees under `.claude/worktrees/`, so `git check-ignore -q .claude/worktrees/x` must succeed; otherwise report it as a `user_setup` item (add `.claude/worktrees/` to `.gitignore` on the feature branch — commit that one line only on confirmation) and do not start: an unignored worktree reads as a leak in the main checkout.

1. **Wave plan**: read each plan's frontmatter. Skip plans whose SUMMARY already exists (resume support). Group the rest by `wave`.

2. **Execute wave by wave** (waves in order; plans within a wave in parallel, each executor in **its own git worktree**, landed onto the feature branch one plan at a time). `{devflow_root}/scripts/flow-land.py` is the only landing authority: it works in the main checkout only, never pushes, refuses the base branch, prints JSON, and exits non-zero on any finding. A finding is `FLOW: BLOCKED` naming it — never retried until green, never worked around by hand. From `wave-start` to `wave-end` the main checkout changes **only through `land`**: no STATE.md rewrite, no commit, no edit — anything else is a leak on the next check. Per wave:
   1. `python3 {devflow_root}/scripts/flow-land.py wave-start --repo <main checkout>` → `wave_base`. A refusal (base branch, detached HEAD, dirty tree, leftover `flow-task/*`) is BLOCKED; `wave-in-flight` is an interrupted wave — resume it per step 3 with the recorded `wave_base`, never start a second one.
   2. Spawn every executor for the wave in **one message, foreground** — never `run_in_background` (isolation is ignored for concurrent background agents: anthropics/claude-code#48811). **Claude native**: pass `isolation: "worktree"` explicitly on every Agent call. **Codex native or cross-provider**: create the worktree yourself — `git worktree add -b flow-task/<NN-MM> <dir>/<NN-MM> <wave_base>`, `<dir>` = `config.json` `worktrees.dir`, else a sibling `../<repo>-tasks` (never inside the repo) — and make it the executor's repo (`--repo <worktree>` to the bridge, per `{devflow_root}/references/hosts.md`). Each executor prompt: the plan path **relative to the repo root**, `.planning/STATE.md` (+ `.planning/ARCHITECTURE.md` and, for UI plans, `.planning/DESIGN.md` when present), template `{devflow_root}/templates/summary.md`, checkpoints `{devflow_root}/references/checkpoints.md`, conventions `{devflow_root}/references/conventions.md` (code under `src/`), the resolved provider and model (for its commit attribution trailers — it cannot observe them itself), the **wave base SHA**, its **task branch** `flow-task/<NN-MM>`, the **main checkout path it must never write to**, and "read the plan and execute it". Keep only each result block (≤15 lines) plus the worktree path and branch the Agent tool result reports.
   3. `leak-check --repo <main checkout>`. Isolation blocks edit tools, not Bash, so this is the enforcement: any change to the main checkout's HEAD, branch, or `git status --porcelain` is BLOCKED with the paths, and nothing lands over it.
   4. Fan-in and scope conformance (below) per plan, against its task branch.
   5. For each completed plan **in plan order**: `land --repo <main checkout> --plan NN-MM --task-branch flow-task/NN-MM --worktree <path>` (add `--host-branch <branch>` when the host created the worktree on its own branch, so that one goes too), then **re-run every `<verify>` of that plan in the main checkout at the new HEAD**. The executor's pass inside its worktree is not evidence for the integrated tree. A failing re-verify is BLOCKED naming the plan; later plans do not land. A verify that leaves untracked files in the main checkout surfaces as a leak on the next land — fix the ignore rules, don't clean up around it. Cherry-picking rewrites SHAs, so a landed SUMMARY's `commits` list names task-branch SHAs; find a plan's commits on the feature branch by trailer (`git log --grep='^DevFlow-Plan: NN-MM'`).
   6. `wave-end --repo <main checkout>`. A leftover task worktree, `flow-task/*` branch, any other branch the wave created, or a land lock is a failure (BLOCKED), never a warning. Then rewrite STATE's Position: executors in worktrees never touch STATE.md, since parallel rewrites of one file would conflict on every landing.

   Negative controls now run inside each executor's own worktree, so a whole-suite `<verify>` is a valid negative control again (`flow-executor` → Negative controls).

3. **Checkpoints**: an executor returning `CHECKPOINT` pauses its plan, not the wave. Present the `need` to the user (with the host question mechanism). Land the wave's other completed plans (2.5) but not the paused one, and hold `wave-end`: the paused plan's worktree and `flow-task/<NN-MM>` branch are kept — its commits are the handoff. Continuation: respawn that executor **without** `isolation` (its branch is checked out in the kept worktree, so a new worktree could not check it out) with the kept worktree path as its repo root, plus plan path, completed tasks/SHAs, and the user's answer; when it completes, `leak-check`, land and re-verify it, then `wave-end`. Checkpoints are human gates even in `--auto` — never answer one yourself; finish the wave's other plans, then stop with a GATE status line carrying the checkpoint content, leaving STATE.md alone (the wave is still in flight). The recorded wave is the resume point: the next run's `wave-start` returns `wave-in-flight` with its `wave_base`. Then a plan whose SUMMARY is on the feature branch has landed; one with a kept task branch continues in its worktree (a continuation re-raises its checkpoint if the answer is still missing); one with neither is spawned fresh at the recorded `wave_base`. A kept worktree that has gone missing is BLOCKED naming its branch — never recreate or discard it silently. An executor that checkpointed on its pinning proof never switched to a task branch: unless the host already cleaned it up, remove the host worktree it was given (`git worktree remove`, no `--force`) and that host branch (`git branch -d`); either refusing is BLOCKED. **Fan-in guard**: before landing, count SUMMARYs against executors spawned — on each task branch (`git cat-file -e flow-task/NN-MM:<phase dir>/NN-MM-SUMMARY.md`), since nothing is in the main checkout until it lands. A missing SUMMARY with no CHECKPOINT is a dead node, never a silent skip. Retry it once, as a continuation in its kept worktree; then ask skip/abort (interactive) or stop with BLOCKED (`--auto`). Skipping a plan whose task branch has commits discards them: the human confirms `git worktree remove` + `git branch -D` explicitly, the same gate as `/flow-workstream drop` — otherwise its leftovers fail `wave-end`. A skipped plan goes in STATE Blockers and the final report — never verify a phase as complete on a partial set.

**Scope conformance** (same point in the wave, before landing, deterministic — no agent judgment): for each plan, compare what it actually committed against what it declared: `git diff --name-only <wave_base>..flow-task/<NN-MM>` versus its `files_modified`. The task branch holds exactly that plan's commits, so no log grep is needed. Paths outside the declaration are **advisory**: report them per plan, record them in the phase report, and continue — this is instrumentation, not a gate. Git already knows what changed and the plan already declared its intent, so the comparison is free and settles a question the verifier can only guess at. Two cases deserve more than a mention: an out-of-scope path that another same-wave plan declared means the disjointness the wave assumed was violated — say so plainly, because the landing of the later plan will conflict or, worse, merge cleanly over the earlier one. A plan that touched none of its declared files did not do what it said it would, whatever its SUMMARY claims. If the wave base or the task branch is unavailable, report the check as **not run** — never as clean.

4. **Verify** after the last wave: spawn `flow-verifier` with the phase dir, `{devflow_root}/references/verification.md`, `{devflow_root}/templates/verification.md`, and `.planning/ARCHITECTURE.md` when present (its `## Smoke` section is the end-to-end gate the verifier runs on every phase). The verifier gets a fresh context and only artifacts on disk — never executor conversations or your run notes; a checker that shares the worker's context is grading its own homework.
   - `gaps` → print them; update STATE (Blockers: gaps, Next: `/flow-plan N --gaps`). Stop. Any gap marked `[REPEAT]` (same failure class as a documented learning or earlier gap) → don't route silently: stop with a GATE status line naming the repeat — the feedback loop failed and the human decides.
   - `human_needed` → present the batched human checks now (walk through, record pass/fail in VERIFICATION.md); any fail → treat as gaps. In `--auto`: don't walk through — stop with a GATE status line listing the checks. Abstained backstop truths (VERIFICATION `unverified`) arrive here too — they are not defects and never route to `--gaps`; each asks the human to decide the rule and pin it with a test, or state it in REQUIREMENTS so it stops being non-inferable. Never resolve one by reading the code and declaring it fine.
   - `pass` → set ROADMAP row verified; append the verifier's learnings bullets to `.planning/LEARNINGS.md` (cap 20 bullets — consolidate oldest when over); update STATE (Position, Next: `/flow-plan N+1` or `/flow-harden` when all phases verified).

4b. **Librarian** (on `pass` only, and only when `.planning/codebase/MAP.md` exists): the map is what tells the *next* phase's planner which conventions to match, so a phase that changed the shape of the codebase and left the map alone has quietly armed the next one to plan against a codebase that no longer exists.

   Read MAP.md's `mapped_sha` and run `git diff --name-only <mapped_sha>..HEAD`. Refresh only when something **structural** moved: a new top-level directory, service, or project; a changed manifest or dependency pin; a new env-var accessor; a changed build/test/run command; a new layer or pattern the next planner would be told to match. Pure feature work inside existing structure does not need a re-map — skip it and say so in one clause. When it does: spawn `flow-mapper` in drift mode with the phase dir, `{devflow_root}/templates/codebase-map.md`, and `since: <mapped_sha>`.

   **Fail-closed** (conventions.md → Fail-closed guards): if `mapped_sha` is absent, or the diff cannot be read (shallow clone, rewritten history), or the mapper fails — report `map: not refreshed ({why})` in the close report and leave both frontmatter fields untouched. Never advance `mapped`/`mapped_sha` for a refresh that did not run: a map that merely *looks* current is the failure this step exists to prevent. Not refreshing is never a gap and never blocks the phase.

5. **Close**: report any scope-conformance findings from step 2 alongside deviations, and the librarian result from step 4b (`map: refreshed` / `unchanged` / `not refreshed ({why})`) — an executor that quietly worked outside its declared files is the same class of signal as a logged deviation, and both belong in the phase's record. Then commit docs (if commit_docs): `chore(flow): phase NN executed + verified`; prepend a `.planning/JOURNAL.md` line (format `{devflow_root}/templates/journal.md`; create if missing); secret-scan the outgoing diff (`git diff <base>...HEAD`, per conventions.md — a hit means no push, GATE status line); then `git push origin <branch>` (origin mirrors the feature branch). Print: plans done, commits, deviations flagged, verification status.

End with the status line per `{devflow_root}/references/autonomy.md` — pass: `FLOW: CONTINUE | phase N verified | next: {/flow-plan N+1, or /flow-harden — /flow-pr on a deploy-N/A project (`deploy.tool: null`), which skips the deploy chain}`; gaps: `CONTINUE` toward `--gaps`; checkpoint/human checks pending: `GATE`; unrecoverable: `BLOCKED`.
