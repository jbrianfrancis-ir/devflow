# Usage report

Opt-in: `"usage_report": true` in `.planning/config.json`. Absent or `false` is off, and nothing on this page happens. Only executor and verifier dispatches are recorded; the report shows every other role as `not instrumented`. The orchestrator — never the agent, which cannot observe its own usage — writes one record per dispatch with `python3 {devflow_root}/scripts/flow-usage.py record --file <the SUMMARY or VERIFICATION.md> --record '<json>'`, the only writer: it validates the record and refuses any `n` but the unit's next, so a repeated step never counts twice. Copy what the host printed, nothing else: Claude native → the Agent result's `<usage>` block (`subagent_tokens` as `tokens`, `duration_ms`), `"source": "agent-tool"`, `outcome` from its result block's status; the bridge → its `usage` object as printed (`source`, `provider`, requested `model`, `tokens`, `duration_ms`, `outcome`), never the wrapper subagent's own block (no `usage` object — the bridge reads `--repo`'s committed config, so a task worktree may not see an uncommitted setting — is `"source": "claude-cli"` or `"codex-cli"` with the rest `"unknown"`); Codex native → `"source": "codex-native"`, `outcome` from its result, the rest `"unknown"`. Add `role` and `n` (1, 2, … per plan, or per phase for the verifier). A value not seen is `"unknown"`, never 0 or an estimate; no prompt, output or other text goes in. Record at the first durable point the skill names. A record still held only in conversation when the run is interrupted, compacted or stopped at a GATE is lost: after a compaction copy one only from a tool result quoted from the session `.jsonl`, never from memory, and a run that did not see a unit's earlier dispatches (a resumed wave) records none for that unit — it then reads `not recorded`, never complete. Shape, coverage and the renderer: `{devflow_root}/scripts/flow-usage.py --help`.
