# Review

## Review before the code exists
`/flow-plan N --panel` adds a judgment panel beside the structural checker. `flow-plan-checker` answers *is this plan executable* (coverage both ways, graph legality, task specificity, size); the panel answers the question no structural check can — *is this the right plan*. Three fresh-context `flow-plan-reviewer` agents run in parallel, one per lens: **scope** (tasks tracing to no requirement, gold-plating, deferred ideas resurfacing — and the mirror, a requirement nothing delivers), **feasibility** (an action hiding a research spike, a `verify` that can't run here, effort an order of magnitude off its neighbours), **coherence** (two plans assuming incompatible shapes of the same thing, a contradicted `D-NN`, a violated `## Principles` entry). Findings dedupe and triage exactly as `/flow-pr`'s do, inside the same revision budget specified in [`plan-format.md`](../plugins/devflow/references/plan-format.md) → Gates. It costs three top-tier agents per round, which is the trade: this is the cheapest moment in the whole workflow to discover you're building the wrong thing.

## Docs-only PRs
Run `/flow-audit --docs` before opening a docs-only PR: it checks the paths, scripts, package scripts, make targets and env names the docs claim against the tree, read-only.

## Review that isn't self-review
`/flow-pr` no longer grades its own homework. It spawns parallel fresh-context `flow-reviewer` agents, one per lens (correctness, security, architecture, conventions, reuse, tests, comprehension, zoom-out, design), selected from what the diff actually touches; findings are deduped across lenses and classified `blocking` / `should-fix` / `nit`, where blocking demands a concrete failure scenario. Findings can be **refuted** with a written reason rather than reflexively obeyed — but refuting a blocking finding is a human gate. The PR body then carries a **Review guide**: the 2–4 files to read first ranked by blast radius, which `must_haves` were proven by a command versus by a code trace, where verification was thin, every deviation, and how many review rounds ran with which lenses — so a reviewer never meets the diff cold. Above the guide, a **Merge Danger** line makes the overall call — `Merge Danger: LOW — two-way door; blast radius: …` — whether a revert fully undoes the merge (a two-way door) or not (one-way), and who is affected if the change is wrong. It informs the merge decision and never gates it. The door and blast-radius framing comes from Matt Pocock's [`pr` skill](https://github.com/mattpocock/skills/blob/main/skills/engineering/pr/SKILL.md) (concept only; only this section was adopted).

Re-review is specified to converge — the diff since the last reviewed SHA, a bug class fixed at every instance in the PR diff, no repeat of a settled or already-fixed finding, rounds recorded in that guide — in [`flow-pr`](../plugins/devflow/skills/flow-pr/SKILL.md) step 2 and [`flow-reviewer`](../plugins/devflow/agents/flow-reviewer.md). A clean round still ends at the human gate in that skill. It does not merge.

**Comprehension and zoom-out lenses:** two lenses look past line-level defects. **Comprehension** asks whether each behavioral hunk can be explained from the code alone — what it does, why, the invariant it relies on, and its blast radius — and files the hunk where one of those has no answer, because code nobody can explain is code nobody can safely change. **Zoom-out** steps back to the system and asks whether the change fits the design that ARCHITECTURE.md, the plan, STATE.md and CLAUDE.md describe — wrong layer, a second way to do one thing, unplanned work, or a doc the diff makes false. `/flow-audit --drift` runs the same doc-against-code question across the whole project rather than one diff. Both ideas are adapted from AI LABS' video [EGM: Google's New Way To Use Claude Code Is Insane](https://www.youtube.com/watch?v=xxf6D9jynFw) (concepts only; nothing was installed and no tool from it is used).

**Tests lens:** Prefer diffs whose new tests are integration/API/behavior proofs of must_haves. Treat large new unit-only suites, wrapper/DTO/DI tests, mock-everything tests, tests without a "protects" reason, per-phase test folders, and "coverage after green" additions as `should-fix` (or `blocking` when they are the only claimed proof). A diff that removes a feature but leaves its tests is `should-fix`. Do not reward classic unit-TDD theater. Full policy: [`test-policy.md`](../plugins/devflow/references/test-policy.md).

## Second opinions
`/flow-oracle`: when you're stuck or facing a high-stakes decision, ask an external frontier model — concepts from [steipete/oracle](https://github.com/steipete/oracle). It is external judgment on work in progress, and it is the escalation the two review surfaces above reach for. `--panel` cross-checks 2–3 models; `--followup` chains onto a prior consult's session. Consults persist in `.planning/consults/` (resumable, with lineage), and DevFlow's rules still apply: the fail-closed secret scan runs over every outbound bundle, every send is a human gate, and advice conflicting with ARCHITECTURE.md pins surfaces as a decision checkpoint — never adopted silently. `/flow-debug` (when hypotheses run dry), `/flow-plan` (checker escalation), and `/flow-harden` (ambiguous findings) offer it at their stuck points. The bundle, engine-detection order, and consult lineage mechanics are specified in [`oracle.md`](../plugins/devflow/references/oracle.md).

## Adversarial review
`/flow-pr --adversarial` raises the bar twice. First the reviewer becomes a *different model*, not just a fresh context: every lens dispatches through the peer provider (Claude hosts route to `codex`, Codex hosts to `claude`) using the same bridge that runs read-only roles under an enforced sandbox — the reviewer's envelope is a property of the dispatch, not a request in a prompt. A missing or failing peer is `BLOCKED`, never a quiet fall back to native, because same-model review reports identically to real review and that is the whole failure being avoided.

## Adjudication in a third context
Then the findings are adjudicated in a third context — the session that received them is about to write the fixes, so it doesn't also get to rule on which are needed. `flow-adjudicator` screens each finding against the durable `.planning/reviews/LEDGER.md`, re-verifies what's left with commands whose output it records, and rules two axes instead of one: a *verdict* (is the finding true) and a *disposition* (what happens about it). Those are different questions, and one word for both is how a real defect gets filed as handled. The full verdict and disposition vocabularies are specified in [`adjudication.md`](../plugins/devflow/references/adjudication.md). On a run without `--adversarial` the reviewers screen that same ledger themselves — or, when no ledger exists yet, the previous round's findings — so the no-repeat rule does not depend on the adjudicator.

## Ledger rules
Three rules give the ledger its weight. **Disproving costs what proving cost** — a `REFUTED` needs a command that ran and its output, not a re-read of the code that defined the behavior. **Dismissal costs something** — a deferral needs the backlog entry to already exist, or it isn't one. **A closed round is immutable** — a later round that overturns an earlier ruling writes a new row citing the one it supersedes, because the record of having been wrong is part of what the ledger is for. Shipping a `CONFIRMED` finding `ACCEPTED AS-IS` is a human gate, named individually at the PR gate and in the PR body: a known defect going out knowingly is a person's call. Full rule text: [`adjudication.md`](../plugins/devflow/references/adjudication.md).

## PR to green
`/flow-ci` takes the PR from opened to mergeable: polls checks, pulls the real failure logs, classifies each failure as caused-by-this-branch / pre-existing-on-base / flake / needs-a-decision, fixes what's its own (with a regression test), and triages bot review threads into fix / refute / defer — replying and resolving each. It never disables a check to get green, never force-pushes, never merges, and never answers a human reviewer. Built for `/loop /flow-ci`.
